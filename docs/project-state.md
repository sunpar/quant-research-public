# Understand the current project

This index describes the checked-out revision of the quant research platform. Read it before starting work, then follow the linked architecture, decisions, questions, and tasks.

## Current capabilities and limits

The repository preserves the imported research and the configured pstack tooling. The [master plan](https://github.com/sunpar/quant-research/pull/1), [foundation](https://github.com/sunpar/quant-research/pull/2), [portable package](https://github.com/sunpar/quant-research/pull/3), [verification speed](https://github.com/sunpar/quant-research/pull/4), and [causal replay](https://github.com/sunpar/quant-research/pull/5) PRs have merged. [The initial PR plan](initial-prs.md) defines the three local increments. All three are implemented.

The [repository runner](../tools/repo.py) and [Make commands](../Makefile) provide locked dependencies, installed Git hooks, snapshot verification, and a guarded PR command. Commit, merge-commit, and rebase hooks run the smoke suite. `make merge` runs the full suite once on the exact commit that lands, then merges it ([D074](decisions.md#d074-run-the-full-suite-only-inside-make-merge)). [Architecture](architecture.md) describes the runner, and [D005](decisions.md#d005-verify-disposable-snapshots-with-prepared-dependencies), [D007](decisions.md#d007-install-the-git-boundary-and-execute-the-selected-snapshots-policy), and [D008](decisions.md#d008-seal-fresh-generations-and-reconcile-publication) record why.

[Portable package storage](../src/quant_research/packages.py), [the CLI](../src/quant_research/__main__.py), and [the Python authoring example](../examples/save_development.py) are implemented. A package preserves supplied trials, retries, repeats, lineage links, exposure events, environment records, and artifact bytes. It can be copied, renamed, inspected, and verified independently of its originating repository. A package records whether its exposure events cover its declared inputs or whether coverage is unknown, and confirmation is unavailable. A package may select no trial and may then supply no trials. `report` and `inspect` handle it, and `compare`, `reconcile package`, and `replay --repeat` or `--retry` refuse it with a named reason ([D060](decisions.md#d060-let-a-package-record-no-selected-trial)). Checksums establish integrity against ordinary changes, not immutable storage or complete historical disclosure.

[Causal replay](../src/quant_research/replay.py) and its [CLI command](../src/quant_research/__main__.py) run a fixed synthetic fixture. One command selects inputs available at each decision, computes a level-difference signal and a descriptive Pearson diagnostic, and saves the evidence as a package. The package keeps the raw input, contract, module source, caller-supplied lock, selected versions, signals, evaluation pairs, and diagnostic. Invalid rows, null results, insufficient pairs, and zero variance have distinct outcomes. Its software exposure events span every timestamp in the raw input, so its packages claim coverage of their declared inputs. Coverage is unknown when the fixture is rejected or supplied history has unknown coverage. [Architecture](architecture.md#replay-the-synthetic-development-fixture) gives the command and the visible cases, and [D010](decisions.md#d010-replay-one-declared-synthetic-causal-profile) records the timing, arithmetic, and evidence rules. [D029](decisions.md#d029-treat-the-latest-membership-vintage-as-complete) records how a later membership vintage replaces an earlier one.

[Package comparison](../src/quant_research/compare.py) and its [CLI command](../src/quant_research/__main__.py) verify two packages and compare their selected trials. The text marks each specification field, input, version, outcome field, and diagnostic metric as same, different, or present in one package only, and it names the lineage relation. It does not rank outcomes. [D034](decisions.md#d034-compare-the-selected-trials-of-two-verified-packages) records the rules.

[Reconciliation](../src/quant_research/reconcile.py) checks a replay package's diagnostic metrics against a reference file and against an exact recomputation from the package's saved raw input. The reference declares a tolerance for every metric. The [CLI command](architecture.md#reconcile-a-replay-package) prints a deterministic record and exits 1 on any disagreement. The bundled reference covers only the synthetic known-answer fixture. The real baseline agreement that closed [Q003](open-questions.md#q003-what-independent-baseline-defines-agreement) comes from the series reconciliation in [D055](decisions.md#d055-run-the-reference-experiment-through-one-audited-pipeline-against-a-frozen-experiment-file). [D035](decisions.md#d035-reconcile-packages-against-declared-tolerances-and-an-exact-recomputation) records the rules.

[Capability evaluation](../src/quant_research/capability.py) supports frozen held-out comparisons and reusable development runs in one local exposure ledger. Each development execution records exposure before dispatch, preserves every repeat, and cannot restore a task to held-out eligibility. The actual research-loop baseline passed three repeats on each of four synthetic supplied-candidate cases, with unknown model versions explicit and resources frozen before the live calls, per [D069](decisions.md#d069-record-a-reusable-development-baseline-through-the-research-loop). These are development results. Independent held-out capability and registry import remain open.

[Model provenance records](../src/quant_research/model_provenance.py) name each model's provider, version, and knowledge cutoff, and keep unknown values explicit. Role versions link each change to a campaign's role assignments, fallbacks, or model versions to the version it replaces. A cutoff check classifies a historical evaluation period against one model's recorded cutoff and gives the sentence a report prints. A role version activates only on a provider route whose live check recorded a go, which today includes Codex and Claude, and campaign resolution builds it ([D062](decisions.md#d062-resolve-a-campaign-revision-into-its-run-authority)). Provider call records name model records, and campaign package reports print their cutoff qualifications, per [D067](decisions.md#d067-archive-each-research-ending-as-a-complete-campaign-snapshot). [D012](decisions.md#d012-record-model-provenance-and-role-versions-as-inactive-data) records the limits.

[Campaign specifications](../src/quant_research/campaigns.py) bind a question to its sources, permitted data, evaluation rules, resource limits, including model-call, wall-time, and token limits, intervention points, model roles, and whether its jobs may run generated code. A researcher creates, revises, and branches them from Python. Each revision is a canonical JSON file named by its SHA-256 and carries forward the trials and exposure events the campaign has already observed. A revision that sets a model-call, wall-time, or token limit is stored under schema version 2, and older revisions keep their bytes and IDs ([D056](decisions.md#d056-make-the-workflow-the-single-accounting-owner-with-durable-call-receipts)). The [campaign runner](../src/quant_research/execution.py) runs one revision's declared jobs. `quant-research campaign start` and `steer` read revision files ([D076](decisions.md#d076-drive-the-research-loop-from-the-cli-and-reconcile-its-receipts-in-status)), and no registry reads campaigns yet. `campaigns.resolve` turns a revision into its run authority. That authority is a run context scoped to the permitted datasets, a corpus of the revision's pinned sources and dataset contracts, the active roles on accepted subscription routes, their prompts, and a tool set bound to that context narrowed to the search cutoff of the frozen rules file that the revision's evaluation digest names ([D065](decisions.md#d065-run-experiments-inside-the-loop-under-a-frozen-search-method)). A live check on 23 October 2026 resolved a pilot campaign and named exactly its datasets, corpus, and active role. The research loop's opening activity resolves each revision it runs ([D063](decisions.md#d063-run-the-platform-owned-research-loop-as-one-temporal-workflow-per-campaign)). P20 also resolves its frozen revisions offline before dispatch ([D062](decisions.md#d062-resolve-a-campaign-revision-into-its-run-authority)). [D013](decisions.md#d013-version-campaign-specifications-as-content-addressed-revisions) records the rules.

[Campaign steering](../src/quant_research/steering.py) records pauses, resumes, cancels, annotations, and methodology steers in an append-only log per campaign, and folding the log gives the campaign's control state. A steer links a revision to its revised child, so earlier trials stay attached. The campaign runner and the research loop enforce the log. Temporal history and complete campaign packages preserve it. The shared registry does not. An event may declare the restrictions of its text, and only declared text reaches a prompt ([D063](decisions.md#d063-run-the-platform-owned-research-loop-as-one-temporal-workflow-per-campaign)). [D031](decisions.md#d031-record-campaign-steering-in-an-append-only-log) records the rules.

[The pilot evaluation profile](../src/quant_research/evaluation.py) evaluates a return series against a declared positive minimum effect. Its intervals use Student's t at a Bonferroni level over the package's recorded trials. It also requires a positive estimate in every subperiod and, with a baseline, tests the intercept of returns regressed on that baseline. Results are supported, null, inconclusive, or invalid input. Each result records the procedure version and the declared minimum effect, subperiod count, and alpha. Replay does not use the profile, because its fixtures yield no period return series. No methodological reviewer has accepted the profile, and it reads no real data. [D015](decisions.md#d015-evaluate-pilot-signals-against-their-recorded-trials) records the procedure and its assumptions, and [D028](decisions.md#d028-keep-replay-descriptive-and-record-evaluation-parameters-with-each-result) records the replay decision.

[Resource accounting](../src/quant_research/accounting.py) admits each attempt against declared campaign limits and reports exact spend by campaign, role, and outcome, with a count of the charges that left tokens or cost unreported. The campaign runner's workflow is its only writer and exports it with each closed run's record. There is no provider pricing, and a subscription call costs no cash. [D016](decisions.md#d016-account-for-resources-in-an-append-only-ledger) records its rules, and [D056](decisions.md#d056-make-the-workflow-the-single-accounting-owner-with-durable-call-receipts) records its single owner and unreported usage.

[Workflow templates](../src/quant_research/workflows.py) define and validate versioned Phase 6 research workflows. The module holds a single-branch baseline and four multi-branch patterns, and nothing executes them. The research loop reads none, so they stay unwired ([D063](decisions.md#d063-run-the-platform-owned-research-loop-as-one-temporal-workflow-per-campaign)). [D017](decisions.md#d017-define-research-workflows-as-validated-versioned-templates) records the contract.

[Source registration and publication](../src/quant_research/sources.py) store original bytes once, keep each caller-declared source occurrence, and publish versioned generations of text chunks located by code-point offsets. Readers pass a trusted run context and see only complete generations whose labels it clears and whose `source_available_at` is at or before its cutoff. Plain text and markdown are supported in a local file store. [Exact retrieval](../src/quant_research/retrieval.py) searches a pinned corpus of these generations by identifier and BM25 and records the units it supplies ([D040](decisions.md#d040-retrieve-exactly-over-a-pinned-eligible-corpus)). A database and embeddings are not implemented. [D018](decisions.md#d018-publish-complete-source-generations-from-a-file-store) records the identities and limits, and [D036](decisions.md#d036-filter-source-reads-through-the-trusted-run-context) records the read filter.

[Source locators](../src/quant_research/locators.py) find equations, tables, figures, and claim sentences in published markdown or plain-text extractions and publish them as versioned generations under the same read filter. Claim detection uses a fixed cue list. Version 2 also reads reference-style images, tables in blockquotes, setext headings, HTML comments, indented code, and CR line endings, and version 1 stays available unchanged. [D043](decisions.md#d043-locate-paper-elements-in-published-extractions) records the rules.

[The review lifecycle](../src/quant_research/findings.py) records claims, findings, and lessons as immutable records with a scope and supporting or contradicting evidence. Only appended review events change a record's status, and only admitted lessons whose supporting records still stand are eligible for reuse. Declarations give external evidence its restrictions, and each record derives its restrictions from what it cites. The registry stores its events. [D019](decisions.md#d019-admit-lessons-only-through-recorded-review-events) records the rules.

[Paper reproduction specifications](../src/quant_research/reproduction.py) are implemented and tested on a synthetic paper. They fix the comparison basis and tolerances before any result and classify each reported target. A specification that pins a published locator generation resolves its equation, table, figure, and claim refs under the caller's run context when it freezes. The reproduction keeps that generation and repeats the check whenever it is built, so a direct build or a replaced specification cannot skip it. Passage and code refs stay opaque. [D020](decisions.md#d020-fix-the-reproduction-comparison-before-results) records the rules.

[Confirmation gating](../src/quant_research/confirmation.py) works on synthetic records. It decides period eligibility from supplied exposure history, refuses a changed frozen shortlist, and returns a restricted report that package exports refuse. Package records still carry unavailable confirmation. [D021](decisions.md#d021-gate-final-confirmation-on-exposure-history-and-frozen-shortlists) records the limits. [Restricted review](../src/quant_research/confirmation_review.py) opens a stored report only under a matching reviewer grant and audits every open, refusal, and grant change ([D048](decisions.md#d048-review-restricted-confirmation-reports-through-audited-grants)).

[Prospective registration](../src/quant_research/prospective.py) persists each terminal campaign procedure, its shortlist, model records, and monthly outcome horizon in a local append-only log. Evidence-bearing observations separate historical initialization from scored rows originally published after registration. Repeated downloads preserve original dates. The actual P16 procedure is registered with zero real prospective observations, and the first future monthly release remains pending. The CLI validates caller-produced evaluations without running a numerical evaluator. [D068](decisions.md#d068-register-campaign-procedures-before-later-released-outcomes) records the rules, verification, and limits.

The [code index](../src/quant_research/code_index.py) describes the Python code of one Git commit from Git objects alone. It lists modules, classes and functions with line spans, the import graph, test references, declared dependencies, and per-file parse failures. The same commit, indexer version, and interpreter give the same bytes. Resolution is static, and nothing consumes the index yet. [D022](decisions.md#d022-index-code-from-git-objects-at-a-pinned-commit) records its rules and limits.

[The research report](../src/quant_research/report.py) renders one verified package as Markdown through `quant-research report`. It lists every trial and attempt with its status and reason, each pilot evaluation's verdict, intervals, subperiods, and parameters, the exposure history, and the package limits, and it makes no claim about investment usefulness. [D023](decisions.md#d023-render-research-reports-only-from-verified-packages) records its rules.

[The pilot data catalog](../src/quant_research/catalog.py) records datasets as documented, manually validated, approved for agent use, or revoked. Each status comes from an append-only log of evidenced transitions. Documentation names the dataset's vintage and the providers approved to receive it. Approval requires validation evidence, digest references for publication, revision, and arrival vintage evidence, and a named timing-and-access adapter. The catalog does not inspect evidence or run an adapter. [D024](decisions.md#d024-catalog-datasets-as-a-log-of-evidenced-transitions) records the rules and limits.

[The dataset adapter](../src/quant_research/datasets.py) serves an approved dataset's rows to a trusted run context. It refuses a dataset outside the run's scope or clearances as a name that does not exist, and an unapproved or revoked one only when the run could otherwise see it, all before opening any file ([D062](decisions.md#d062-resolve-a-campaign-revision-into-its-run-authority)), supplies each row's latest revision available by the cutoff, and records the read so that it replays to the same rows. It opens the vintage that the documentation in force names. A process parses each stored vintage once and still checks the file's bytes on every read ([D065](decisions.md#d065-run-experiments-inside-the-loop-under-a-frozen-search-method)). [D045](decisions.md#d045-read-approved-datasets-through-a-timing-and-access-adapter) records the rules and limits.

[Public data ingestion](../src/quant_research/public_data.py) pulls ALFRED `UNRATE` vintages, FRED `SAHMREALTIME`, and the Ken French monthly 3 factors through `quant-research data pull` and `data ingest`. It keeps each download's original bytes and retrieval time, stores each converted dataset under its vintage digest so every earlier read record still replays, and leaves each dataset documented. Only `data validate` and then `data approve` make a dataset readable to agents. A live run on 22 October 2026 ingested all three datasets twice with unchanged digests. The researcher's data root holds the pilot, search, and paper datasets, validated and approved for both subscription routes on 23 October 2026 ([pilot brief](phase0-pilot.md#pin-the-data)). [D052](decisions.md#d052-ingest-the-pilots-public-data-into-a-vintage-addressed-store) records the timing conventions and limits.

The Phase 3 paper case is registered. `public_data.register_paper` registers a Markdown conversion of Estrella and Mishkin's Federal Reserve Bank of New York Research Paper 9609, the May 1996 working paper of their 1998 article, in a data root's source store. It publishes the paper's chunk and locator generations there. The 1998 article is closed access, so the case reproduces the working paper. The paper's 10-year and 3-month Treasury rates and its NBER recession quarters ingest as `alfred.gs10`, `alfred.tb3ms`, and `alfred.usrecq`, whose vintages all begin after the paper's 1959 to 1995 sample. A live check on 22 October 2026 looked up Table 2 in a fresh root, and its cells matched the scanned page. An agent chose the version and the series under the user's autonomy grant, and the researcher approved them on 23 October 2026. The researcher validated and approved the series on 23 October 2026. The appendix tables have since been inspected cell by cell, with two readings unresolved because of scan damage. [D070](decisions.md#d070-register-the-estrella-and-mishkin-working-paper-and-its-fred-series) records how the version differs from the article, how the conversion was checked, and the limits.

[The paper reproduction](../src/quant_research/probit.py) freezes a specification of Table 2's SPREAD row, eight in-sample probit fits with a pseudo R² and a t-statistic each, on adapted data. A plain-Python probit estimator with Newey-West standard errors fits them from the approved series. A live run on 23 October 2026 reproduced one of the eight pseudo R² values within half a printed unit and missed the other seven by 0.0018 to 0.0222. All eight t-statistics are inconclusive, because the paper does not state its Newey-West lag. An agent chose the table, the comparison basis, and the tolerances under the user's autonomy grant, and the researcher approved them on 23 October 2026 by accepting the coordinating agent's recommendation. [D071](decisions.md#d071-reproduce-table-2s-spread-probit-on-adapted-fred-data) records the specification, the sources checked, the run, and the limits.

[Signal programs](../src/quant_research/signals.py) express the real-time Sahm indicator in five typed operators. They evaluate it once per decision month from the `UNRATE` vintage available at the end of the previous month, read through the dataset adapter. `quant-research reconcile series` compares the recomputed series with FRED's `SAHMREALTIME`, and `reconcile package` now names the package reconciliation. The researcher has not accepted the months a live run excluded. [D053](decisions.md#d053-evaluate-signal-programs-per-decision-and-reconcile-the-sahm-series-with-fred) records the missing-month convention, the exclusions, and the limits.

The same operators now form a bounded search grammar, with lags, ratios, logical combinations, and reads of an earlier decision's vintage. Every parameter has a declared range and every program a size limit. `parse` rejects a program that reads past its decision's vintage, uses a negative lag, or names a dataset outside the approved search universe, each with a named reason, and `digest` names a program by its canonical JSON. The search universe is `UNRATE`, payrolls, industrial production, and manufacturing hours. An agent chose it under the user's autonomy grant on 22 October 2026, and the researcher approved it on 23 October 2026. A live check evaluated three programs over those series and left the Sahm reconciliation unchanged. [D064](decisions.md#d064-search-signal-programs-in-a-bounded-grammar-over-a-chosen-alfred-universe) records the grammar, the universe, and each series' read cost.

[Backtests](../src/quant_research/backtest.py) compute an allocation's monthly returns from the approved Ken French factors with two engines. `plain` computes in `Fraction` and is the reference. `vectorbt` runs vectorbt 1.2.0 as the stand-in for the firm backtester. Each switch costs 10 basis points of the portfolio value at the start of its month. `compare` reports the largest monthly difference between the engines against a declared tolerance of 1e-12. A live run on 22 October 2026 agreed within 3.4e-16 over the 1202 months from July 1926 to August 2026. The reference experiment calls both. [D054](decisions.md#d054-backtest-allocations-with-a-plain-reference-and-a-vectorbt-engine) records the cost convention, the vectorbt layout, the tolerance, and the timing.

[The isolated worker](../src/quant_research/worker.py) runs generated signal code in a Docker container, built by `make worker-image` from a base pinned by digest. The container has no network or host credentials. It sees only the adapter's slice and the source, and runs as a non-root user under read-only, process, memory, CPU, and time limits. Only a validated signal file returns. The image adds numpy and pandas locked by version and hash, and a local run log keeps each container run's record and outcome across restarts. The campaign runner calls it for jobs whose campaign specification enables generated code, and the `run_signal` agent tool calls it when the operator binds a run log. Both log each container run, and the registry stores a run log's entries when the operator imports it. [D047](decisions.md#d047-run-generated-signal-code-in-a-locked-down-container) records the rules and limits.

[Restriction labels and run contexts](../src/quant_research/access.py) are implemented. Source and dataset reads use the read check, exact retrieval and agent tools read through them, and provider calls use the send check. Material carries labels, provider approvals, and an availability time, and a run's trusted context decides what it may read or send to a named provider. A context may also carry a campaign's dataset scope. A mapped contract also binds permitted month intervals into authority; direct reads, tools and numerical consumers enforce them, while frozen legacy contracts retain their original behavior ([D081](decisions.md#d081-enforce-permitted-months-through-pinned-dataset-contracts)). [D025](decisions.md#d025-carry-restrictions-with-material-and-authority-with-the-run) records the rules.

[The provider boundary](../src/quant_research/providers.py) is implemented with local fake adapters. Every call passes the run context's send check and the provider's versioned label policy before its adapter runs, and fallbacks pass the same check. A call sends only under call IDs that the campaign workflow minted and reserved. The gateway claims each ID in a local call log before its adapter runs and stores the reply after it, so a resumed activity reuses a stored reply and never sends one ID twice. Each call keeps what it sent and the reply as content-addressed transcripts, and its record names the configured model, the runtime, and the model the provider reports it served ([D061](decisions.md#d061-run-model-calls-and-tool-calls-as-activities-that-stop-their-adapters)). A usage cap is recorded as `rate_limited`. The gateway charges no ledger, and the workflow charges the receipts that a close step returns. Schema 4 adds fixed-token failure reasons while preserving version 3 logs and recorded activity results ([D077](decisions.md#d077-align-recovery-records-and-pinned-lesson-authority)). The Claude Code and Codex adapters below are the only real adapters, and no SDK exists. [D041](decisions.md#d041-check-outbound-provider-content-against-the-run-and-a-versioned-provider-policy) records the policy rules, and [D056](decisions.md#d056-make-the-workflow-the-single-accounting-owner-with-durable-call-receipts) records the receipts.

[Agent tools](../src/quant_research/agent_tools.py) expose corpus search, dataset listing, dataset contracts, dataset reads, paper location lookup, admissible lessons, and generated signal runs to a model as seven typed tools. The trusted run context, stores, catalog, and review log are bound when the tool set is created, as is a run log when the run enables generated code, and no argument can name a cutoff, clearance, corpus, memory pin, or context. Each call returns a result or a refusal with a fixed message, and its record replays byte-identically. A signal run's record replays against its run log without starting a second container. Lessons return only when eligible at the context's memory pin and readable under the restrictions derived from their cited evidence. The returned restrictions use that same exact review-log prefix ([D077](decisions.md#d077-align-recovery-records-and-pinned-lesson-authority)). Each call renders as gateway material whose restrictions derive over everything the tool read, so a dataset approved only for the firm proxy cannot reach a subscription route. A search returns at most 20 units and a rendered result at most 262,144 bytes ([D059](decisions.md#d059-render-each-tool-call-as-gateway-material-under-the-restrictions-of-what-it-read)). `list_datasets` names only the datasets a read would supply, and `describe_dataset` returns the contract parts that the run's cutoff admits ([D062](decisions.md#d062-resolve-a-campaign-revision-into-its-run-authority)). The tool activity runs them, and the research loop schedules it. [D049](decisions.md#d049-expose-evidence-to-agents-through-typed-tools-bound-to-the-run-context) records the rules.

[Runner activities](../src/quant_research/activities.py) run model calls and tool calls as Temporal activities under the authority of the campaign revision each one names. `ask_model` runs one model attempt from its lease to its close and returns its receipts for the workflow to charge. A workflow cancel or the activity's own deadline sets the adapter's cancel event, so the call records `cancelled`, and a call whose worker died resumes under its lease. A failure reaches the workflow as a fixed error with no backing text. The research loop and new `CampaignRun` model jobs call this helper. Repeated cancellation keeps the same close activity alive until its receipts arrive. Both workers share the close implementation, and starting `CampaignRun` on an open research loop returns a named refusal ([D077](decisions.md#d077-align-recovery-records-and-pinned-lesson-authority)). [D061](decisions.md#d061-run-model-calls-and-tool-calls-as-activities-that-stop-their-adapters) records the original activity qualification, and [D080](decisions.md#d080-run-new-campaign-model-attempts-through-workflow-owned-settlement) records the new campaign protocol and compatibility limits.


[The research loop](../src/quant_research/research.py) runs one campaign revision as one Temporal workflow that asks the researcher role for each step and runs it. A step is a tool call, an experiment, a conclusion, or a stop. An experiment runs one search program through P04's pipeline on the search window of the campaign's frozen rules file, and every candidate, rejected and failed ones included, becomes the next trial of the campaign's one package lineage. Tools and experiments read only data available by the search cutoff, 1 January 2005 for the pilot, and the window from 2005 is held back for P16's final evaluation. Each request's restrictions derive over everything in it, its bytes stay within 384 KiB, and undeclared steering text never enters it.
